# verge-latency-switcher — 需求、UI 设计与实现路径

## 1. 核心需求
- 功能性插件：通过 Clash Verge Rev 外部控制器（Clash Meta/mihomo API）实现自动节点延时巡检与切换
- 定时检测：每隔 N 分钟（可自定义，默认 5 分钟）刷新节点延时，重新判断当前选中节点延时
- 判定阈值：延时 <= 220ms 时不改变当前节点；> 220ms 时执行切换策略
- 切换策略（按优先级）：
  1. 同国家/地区：筛选同一国家区域内延时 <= 220ms 且非当前节点 → 按延时升序取最低，优先切换
  2. 全组：若同国家无符合条件节点，在全组内筛选延时 <= 220ms → 按延时升序取最低延时切换
  3. 订阅兜底：若全组均 > 220ms，切换订阅服务（轮换预设的 Profile/订阅配置）
  4. 重检测：切换订阅后重新检测节点延时，按 1–2 优先级尝试切换到符合要求的节点
  5. 最终兜底：若仍无任何 <= 220ms 节点 → 关闭系统代理，并弹出系统原生提示窗口说明原因
- 配置灵活：定时时长（分钟）、延时阈值（ms）、目标策略组、优先同国家、外部控制器地址/密钥、静默模式等均可自定义
- 稳定可靠：性能开销小、无报错、后台常驻、不频繁抖动
- 测试安全：test_mode=true 时仅记录日志，不弹窗、不关闭系统代理

## 2. 技术实现方式
- 实现形式：独立常驻程序（Python 版），通过外部控制器 REST API 控制 mihomo
- API 要点：GET /proxies、PUT /proxies/{group}、PATCH /configs、GET /version
- 国家识别：基于节点名称关键词（国旗 emoji 优先）映射
- 进程与日志：logs/app.log 运行日志；logs/app.pid、logs/watchdog.pid 供守护进程与自启脚本识别进程
- 后台：pythonw.exe 无控制台启动
- 环境：Windows 10/11、Python 3.12+（UI 使用标准库 tkinter，无需额外安装 PyQt5）
- 开机自启/跟随代理：watchdog.py 守护进程随登录自启，监听系统代理开关（注册表 ProxyEnable/ProxyServer），开则拉起 app.py、关则结束 app.py

## 3. UI 设计（简约，适配 Windows 10/11）
- 窗口：480×420，标题「Verge 延时自动切换」，无控制台黑窗（pythonw 启动）
- 布局：垂直，分为「设置」「运行日志」两个区块
- 设置项：定时时长（1–120）、延时阈值（50–2000）、目标策略组、API地址、密钥（密码模式）、优先同国家、静默模式、开机自启(随系统代理开关)、保存按钮
- 日志区：只读文本框，每 2 秒刷新，自动滚到底部，保留最近 20000 字符
- 系统托盘：图标（icon.ico）常驻右下角，右键菜单「打开界面 / 隐藏界面 / 退出」；点窗口关闭按钮仅最小化到托盘
- 单进程架构：app.py 同时承载 后台巡检线程 + UI + 托盘
- 启动行为：手动启动（启动.vbs 传 --show）显示设置面板；开机自启/随系统代理自动拉起时默认后台静默，仅驻留托盘

## 4. 实现路径
1. 配置读写 config.json（热加载）
2. API 封装
3. switcher.py 核心逻辑
4. 国家匹配
5. 日志系统
6. ui.py 简约 UI（tkinter）
7. app.py 单进程整合（后台巡检线程 + UI + 系统托盘）；启动.vbs 无黑窗运行
8. 安全机制
9. watchdog.py 守护进程 + 启用/禁用开机自启.vbs（跟随系统代理开关）

## 5. 文件清单
- app.py 入口（后台线程 + UI + 托盘）
- ui.py 设置界面（tkinter）
- switcher.py 后台巡检/切换核心
- watchdog.py 守护进程（跟随系统代理）
- autostart.py 开机自启实现（注册表 Run 键 + 启停守护进程，UI 与脚本共用）
- icon.ico / icon.png 托盘与窗口图标
- config.json
- 启动.vbs（无黑窗启动，推荐）/ 启动.bat
- 启用开机自启.vbs / 禁用开机自启.vbs
- logs/app.log、logs/app.pid、logs/watchdog.pid（运行后生成）
- README.md
- 需求与实现路径.md

## 6. 使用说明
1. 开启 Clash Verge Rev 外部控制器（127.0.0.1:9090），填好 API 密钥
2. 双击 启动.vbs 启动（无黑窗；后台核心 + UI + 托盘）
3. UI 中调整参数并点击「保存设置」
4. 测试阶段保持 test_mode 勾选，确认正常后取消勾选正式启用
5. 需要开机自启：双击 启用开机自启.vbs；取消则双击 禁用开机自启.vbs
